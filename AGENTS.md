# AGENTS.md

This file provides guidance to coding agents working in this repository.

## What this is

`tl-parser` is the Python binding of `astral-tl` (crate name: `tl`), a
zero-copy Rust HTML parser library. It exposes a DOM-like API backed by an
arena of `Node` objects indexed by `NodeHandle` through the `tl` Python
module. The extension is implemented with PyO3 and built and packaged with
`maturin`.

## Important files

- `pyproject.toml` contains the Python package metadata and `maturin` settings.
- `Cargo.toml` defines the Rust crate and Rust package metadata that can flow
  into the wheel metadata.
- `src/python.rs` contains the PyO3 bindings exposed by the extension module.
- `python/tl/__init__.py` re-exports the extension; `python/tl/tl.pyi` is the
  typing surface for Python users.
- `python/tests/` contains the Python API smoke tests.
- `README.md` is both the project documentation and the package long
  description included in distributions.

## Development commands

```bash
# Create or update the development environment
uv sync

# Build and install the extension for local development
uv run maturin develop

# Run Python tests
uv run pytest

# Run the Rust checks used by CI
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test
```

For a release-style wheel, use:

```bash
uv run --with 'maturin>=1.5,<2.0' maturin build --release
```

## Architecture and workflow

The Rust `cdylib` exposes the PyO3 bindings. `maturin` builds the `tl`
extension and places it alongside the small Python wrapper in `python/tl/`.

When changing the Python API:

1. Update the binding implementation in `src/python.rs`.
2. Update `python/tl/tl.pyi` when the public signatures change.
3. Add or update a focused test in `python/tests/`.
4. Update `README.md` when the supported public API or installation flow
   changes.

Do not replace the `maturin` build with a Python-only packaging tool. Avoid
changing the underlying Rust parser unless the Python surface requires it.

## Package metadata and releases

Keep `pyproject.toml` and the relevant package metadata in `Cargo.toml` aligned
with `https://github.com/mgaitan/tl-parser`. In particular, `readme`, project
URLs, and the Cargo homepage affect the metadata generated by `maturin`.

The wheel workflow builds Python 3.12, 3.13, and 3.14 wheels for Linux,
Windows, and macOS, then publishes them to PyPI from a GitHub release. Verify
the generated wheel metadata when changing package metadata:

```bash
uv build
```

Version values are currently kept in both `pyproject.toml` and `Cargo.toml`;
update them together when preparing a release.
